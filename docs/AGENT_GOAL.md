# Cursor 에이전트 작업 목표

사용자가 멈추라고 할 때까지 계속한다. 예약 작업은 만들지 않는다.

## 현재 목표
자율 개선 대상과 차수 순환은 저장소 밖의 비공개 로컬 문서 `D:\VideoCreator\own-model\GOAL.md`가 정한다. 이 문서에는 공개
프로그램(이 저장소)을 고칠 때의 규칙만 둔다. 비공개 문서가 다루는 코드·설계·장면·결과는 이 저장소에 넣지 않는다.

## 최우선 규칙
저장공간이나 연산이 필요한 모든 것은 D 드라이브(`D:\VideoCreator` 아래)에서 실행한다. C는 포터블 OS이므로 모델·캐시·임시
파일·결과·계획·보고서를 C에 두지 않는다.

## 공개 프로그램 범위
- 이 PC(16GB RAM, Intel Iris Xe)에서 Cursor 요청으로 현장 영상을 만드는 로컬 도구다.
- 상업 조건이 붙은 모델(LTX 등)은 자동으로 고르지 않는다. 요청이 이름을 지정할 때만 실행하고, 결과물에는 기계 생성 표시를
  남긴다. 권리 정리는 [MODEL_LICENSES.md](MODEL_LICENSES.md)를 따른다.

## 일하는 방식
- 가만히 기다리지 않는다. 생성과 테스트는 백그라운드로 띄우고 그동안 다른 일을 한다. 상태는 일 사이에 로그 끝 한 줄로만
  확인한다. `AwaitShell` 장시간 대기, `sleep`, 반복 조회, 로그 전체 읽기를 하지 않는다.
- 독립인 일은 동시에 실행한다. 맥락이 작은 독립 작업은 하위 에이전트에 맡기되, 같은 파일을 동시에 고치지 않는다.
- 바뀐 부분의 테스트를 돌린 뒤 배포한다. 끝나면 임시 폴더, 실패·취소 작업, 이전 버전 산출물을 정리한다.

## 커밋·푸시 (`prototype` 브랜치)
- 전체 테스트가 통과할 때만 푸시한다. 실패하면 원인부터 고친다.
- 개인 경로(사용자 폴더), 사용자 이름, 팀 프로젝트 내용(실제 회사·현장 이름, 팀 장면 목록), 비공개 모델 내용이 없어야 한다.
- D 실행 폴더의 계획·보고서·영상·키프레임은 넣지 않는다. 강제 푸시, 기록 덮어쓰기, 다른 브랜치 푸시를 하지 않는다.
- 큰 다운로드(1GB 초과), 클립 이어 붙이기·루프·보간, 외부 API, 안전 검사 우회는 하지 않는다.
