# Cursor 에이전트 자율 개선 목표

[GPT_GOAL.md](GPT_GOAL.md)와 같은 원칙을 Cursor 에이전트가 직접 수행하도록 맞춘 버전이다. 사용자가 멈추라고 할 때까지 계속한다. 예약 작업은 만들지 않는다.

## 최우선 규칙
저장공간이나 연산이 필요한 모든 것은 D 드라이브(`D:\VideoCreator\CursorVideoRuntime`)에서 실행한다. C는 포터블 OS이므로 모델·캐시·임시 파일·결과·계획·보고서를 C에 두지 않는다. D 루트에는 쓰기 권한이 없으므로 `D:\VideoCreator` 아래만 쓴다.

## 궁극의 방향(유일하게 고정)
이 PC(16GB RAM, Intel Iris Xe)에서 Cursor 대본만으로, 장비와 작업자가 함께 자연스럽게 움직이는 현장 연속 영상을 만드는 로컬 생성기를 계속 개선한다.

## 1차 목표
장비 1대와 작업자 1명이 끝까지 보이고 화면이 무너지지 않는 짧은 영상을, 이 PC에서 Cursor 요청으로 다시 만들 수 있게 한다.

- **통과 기준:** 검증 장면 1개 이상이 7/10점 이상.
- 이후 목표는 고정하지 않고, 차수마다 결과를 근거로 스스로 설계한다.

## 차수 순환
1. **상태 읽기:** `D:\VideoCreator\CursorVideoRuntime\reports\STATE.json`만 읽는다.
2. **목표 설계:** 궁극의 방향과의 가장 큰 격차 하나를 고른다. 목표 1개, 가설 1개, 통과 기준을 실행 전에 적는다. 장면, 시드, 시도 횟수(계획당 최대 6회)도 미리 고정한다.
3. **구현:** 그 가설에 필요한 코드나 설정만 바꾸고, 바뀐 부분의 테스트만 돌린 뒤 배포한다.
4. **실행:** 계획 JSON을 `D:\VideoCreator\CursorVideoRuntime\plans\`에 쓰고, `video.cmd plan`을 백그라운드 셸(`block_until_ms: 0`)로 시작한다. 실행 단위마다 `reports\<계획>-<시각>\<id>.json` 요약이 생기므로, 그 파일이 생기면 끝나는 감시 셸을 하나 더 걸어 신호로 받는다. 신호가 오면 그 요약 1개만 읽는다.
5. **판정:**
   - 자동 경고로 먼저 거른다.
   - 최고 후보 1개의 대표 이미지(`review_image`)를 D 경로에서 바로 연다. 복사본을 C나 수업 저장소(`ai-test`)에 두지 않는다.
   - 대표 이미지로 갈리지 않는 핵심 동작(작업자가 가려진 곳에서 나오는 순간, 짧은 후진, 손 신호)은 `video.cmd strip <작업> --box x0,y0,x1,y1 --from 초 --to 초`로 그 영역·구간만 확대해 확인한다.
   - 움직이는 사람은 동작 중 4~6시점을 원해상도(2배 확대)로 본다. 몸이 뭉개지거나 녹아내리면, 소품이 사라지거나 몸에 붙으면, 대본에 없는 동작이 끼면, 크기·밝기·원근이 주변과 맞지 않거나 땅 위에서 미끄러지면 실패다. 위치가 맞아도 통과가 아니다.
   - 첫 프레임은 Cursor `GenerateImage`(사용자 승인됨)로 만들고 바로 `video.cmd import <이미지>`로 D 실행 폴더에 옮긴다(원본 삭제). 이미지 생성을 못 쓰면 `video.cmd frames <spec>`으로 SD1.5 후보를 만들어 비교 이미지 한 장으로 고른다. 고른 프레임은 장면의 `image_path`로 넘긴다.
   - 판정표: 장비, 작업자, 끝까지 유지, 형태, 붕괴 없음. 각각 0~2점.
6. **채택:** 통과 기준을 넘고 최고 기록보다 나을 때만 새 최고로 채택한다.
7. **기록·정리·보고:** `STATE.json`을 갱신하고, 아래 저장공간 최적화 루틴을 돈 뒤 사용자에게 5줄 이내로 보고한다. 그다음 다음 차수 계획을 바로 실행한다.
8. **자동 푸시:** 다음 차수 생성을 백그라운드로 시작한 뒤, 기다리는 동안 저장소에 바뀐 내용이 있으면 바로 커밋·푸시한다(`prototype` 브랜치). 푸시 전에 반드시 확인한다.
   - 변경 내용에 개인 경로(사용자 폴더), 사용자 이름, 팀 프로젝트 내용(실제 회사·현장 이름, 팀 장면 목록)이 없을 것. 걸리면 그 부분을 빼고 푸시한다.
   - 전체 테스트가 통과할 것. 실패하면 푸시하지 않고 원인부터 고친다.
   - 커밋 메시지는 바뀐 이유를 짧게 적는다. 실행 폴더(D)의 계획·보고서·영상·키프레임은 저장소에 넣지 않는다.

## 낭비 차단
- 반복 조회, `AwaitShell` 대기, 로그 전체 읽기, 바뀐 변수가 없는 재실행을 금지한다.
- 생성을 기다리는 동안 놀지 않는다. 생성기 로직의 개선·최적화·정리를 이어 가고, 기본값을 바꾸지 않는 변경은 테스트 후 바로 배포한다(진행 중인 작업은 시작할 때 읽은 코드로 끝난다). 할 일이 결과에 달려 있을 때만 턴을 끝내고 신호를 기다린다.
- 같은 가설이 두 차수 연속으로 개선되지 않으면 그 방향을 보류한다.
- 서로 다른 가설로 세 차수 연속 개선이 없으면 생성을 멈춘다. 재개 조건을 기록하고 보고한 뒤 대기한다.
- 큰 다운로드(1GB 초과), 클립 이어 붙이기·루프·보간, 외부 API, 안전 검사 우회는 금지한다.
- 커밋·푸시는 8단계 규칙에 따라 차수마다 자동으로 한다. 강제 푸시, 기록 덮어쓰기, 다른 브랜치 푸시는 하지 않는다.

## 저장공간 최적화 루틴
차수마다 `STATE.json`을 갱신한 직후 한 번 돈다. 남길 것을 먼저 정하고, 나머지만 지운다.
1. **실행 폴더:** `video.cmd clean`으로 지울 목록을 먼저 본다(지우지 않음). 지울 작업이 맞으면 `video.cmd clean --apply`.
   - 남긴다: `STATE.json`에 작업 ID가 적힌 작업(채택본과 판정 근거), 대기·실행 중 작업, 모델, 모델 무결성 기록, 자원 학습 기록, 문장 인코딩 캐시.
   - 지운다: 실패·취소 작업(1시간 뒤), `STATE.json`에 없는 완료 작업과 클립 캐시(3일 뒤), 남은 임시 폴더(엔진이 쉬면 1시간, 돌고 있으면 하루 뒤), 작업이 사라진 요청 색인.
   - 탈락했어도 근거로 남길 작업은 `STATE.json`에 작업 ID를 적어 지킨다.
2. **계획·보고서:** 결론을 `STATE.json`에 옮긴 차수의 계획과 보고서 폴더는 지운다. 대기 중이거나 판정 전인 계획은 남긴다.
3. **첫 프레임·키프레임:** `assets`에는 채택본과 남은 계획이 쓰는 이미지만 둔다. 편집 원본과 비교용 사본은 쓰고 바로 지운다.
4. **C 드라이브:** 우리 작업이 C에 남긴 것(가져오기 전 이미지, pip·Hugging Face 캐시)은 차수마다 지운다. 사용자 임시 폴더의 하루 넘은 항목은 사용자가 정리를 요청했을 때 지운다(사용 중인 파일은 건너뛴다).
5. **모델:** 루틴에서는 지우지 않는다. 기본 모델과 문서에 적힌 대체 경로에 쓰이지 않는 모델은 크기와 함께 보고하고, 사용자가 정리를 요청했을 때 지운다. 다시 받으려면 1GB 초과 다운로드가 되므로 확실히 안 쓰는 것만 고른다.
6. **여유 공간:** `clean` 결과에 `low_free_space` 경고(실행 폴더 드라이브 여유 10GiB 미만)가 뜨면 1~4를 다시 한다. 그래도 부족하면 생성을 멈추고 보고한다. 긴 영상은 프레임을 쓰고 페이지 파일을 늘릴 수 있다.
7. **건드리지 않는 것:** 사용자 개인 파일, 다른 프로젝트 폴더, 휴지통, 이전 Windows 설치 같은 시스템 폴더는 사용자가 지목했을 때만 지운다.
