# 자율 개선 작업 프롬프트 (복사해 사용)

## 궁극의 방향
이 PC(16GB RAM, Intel Iris Xe)에서 Cursor 대본만으로, 장비와 작업자가 함께 자연스럽게 움직이는 현장 연속 영상을 만드는 로컬 생성기를 계속 개선한다. 이 방향만 고정한다. 중간 목표, 방법, 모델, 길이 단계는 고정하지 않는다. 사용자가 멈추라고 할 때까지 스스로 판단하고 개선을 이어간다.

## 1차 목표(첫 차수만 지정)
장비 1대와 작업자 1명이 끝까지 보이고 화면이 무너지지 않는 짧은 영상을, 이 PC에서 Cursor 요청으로 다시 만들 수 있게 한다. 이것이 초기 모델이다.

- **통과 기준:** 고정한 검증 장면 1개 이상이 판정표 7/10점 이상.
- "모델"은 공개 가중치와 생성 설정의 조합이며, 새로 학습한 가중치로 부르지 않는다.

## 차수 순환(매 차수 반복)
1. **상태 읽기:** `reports/STATE.json`만 읽는다. 다른 문서와 로그는 이번 가설에 필요한 부분만 읽는다.
2. **목표 설계:** 직전 결과와 궁극의 방향 사이에서 가장 큰 격차 하나를 고른다. 그 격차를 줄일 이번 차수의 목표 1개, 검증 가능한 가설 1개, 통과 기준을 실행 전에 적는다. 장면, 시드, 자원, 시도 횟수도 미리 고정한다.
3. **구현:** 그 가설에 필요한 코드나 설정만 바꾼다.
4. **실행:** 생성은 `video.cmd plan <계획.json>`을 백그라운드로 돌린다. 계획당 실행은 최대 6회다. 결과는 요약(4KiB 이하)만 읽는다.
5. **판정:**
   - 먼저 자동 경고(어두워짐, 색 붕괴, 검은 프레임, 정지)로 거른다.
   - 경고가 없는 최고 후보 1개만 대표 이미지로 보고 판정표를 매긴다. 항목은 장비, 작업자, 끝까지 유지, 형태, 붕괴 없음이고 각각 0~2점이다.
6. **채택:** 통과 기준을 넘고 최고 기록보다 나을 때만 새 최고로 채택한다. 품질을 떨어뜨린 속도 향상은 채택하지 않는다.
7. **다음 차수 설계:** 목표를 통과했으면 궁극의 방향을 기준으로 다음 격차를 스스로 골라 새 목표를 설계한다. 통과하지 못했으면 원인을 근거로 가설을 바꾼다. 그다음 1번으로 돌아간다.

다음 목표를 고를 때 우선순위는 고정하지 않는다. 사용자 효과, 성공 가능성, 검증 비용을 근거로 비교한다. 참고로 볼 만한 격차는 대상 유지, 행동의 자연스러움, 길이(8초 → 15초), 새 대본 일반화, 성공률, 처리 시간, 메모리다.

## 낭비 차단(반드시 지킴)
- 상태 반복 조회, 긴 대기, 로그 전체 읽기, 바뀐 변수가 없는 재실행을 금지한다.
- 같은 가설이 두 차수 연속으로 개선되지 않으면 그 방향을 보류한다.
- 서로 다른 가설로 세 차수 연속 개선이 없으면 생성을 멈춘다. 재개 조건(새로 필요한 근거나 자원)을 기록하고, 사용자에게 보고한 뒤 대기한다.
- 실행 중인 작업이 있으면 완료 알림을 기다린다. 빈 조회나 빈 판단을 반복하지 않는다.
- 금지:
  - 클립 이어 붙이기, 루프, 보간, FPS 변경으로 길이 늘리기
  - 외부 API·클라우드
  - 안전 검사 우회
  - 사용자 승인 없는 1GB 초과 다운로드

## 자원 원칙
쓸 수 있는 만큼 쓰고, 여유가 생기면 더 쓰고, 부족하면 느리게 진행한다. RAM 부족을 이유로 포기하지 않는다. 멈추는 기준은 commit 고갈뿐이다.

## 차수 종료 시
`reports/STATE.json` 하나만 갱신한다.

```json
{"round": 4, "direction_gap": "대상 유지",
 "best": {"score": 7, "settings": "...", "video": "...", "length_s": 2},
 "last": {"goal": "...", "hypothesis": "...", "score": 6, "adopted": false, "reason": "..."},
 "paused_hypotheses": ["..."], "stall": {"same": 1, "any": 1},
 "next": {"goal": "...", "hypothesis": "...", "pass": "..."}}
```

사용자 보고는 5줄 이내로 한다: 이번 목표와 가설, 점수(최고 대비), 채택 여부, 스스로 정한 다음 목표, 막힌 점.
