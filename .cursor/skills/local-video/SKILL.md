# Local video

Design for the user's 16GB LG Gram with Intel Iris graphics and little free RAM. The current RTX computer may test compatibility only. Use the installed local-video MCP tools. Runtime files stay in the selected C/D SSD folder.

1. Call video_doctor once. Report the selected device, actual GPU scope and readiness. Default Neo streams BF16 video Linear matrices to OpenCL with 64MiB explicit buffers and 5GiB process working-set limit; attention, text, VAE and safety remain CPU. Auto prefers a discrete GPU, then integrated GPU. Never imply that encoding or a device flag proves neural GPU execution. Forced GPU failure must be visible. Do not raise limits or close unrelated applications.
2. Preserve the Korean script. Translate it once to a short English motion prompt, with a fixed composition, stable light and one modest action. Use a matching site_template from video_site_presets only when it matches the requested action. Otherwise use scenes and domain="construction". Neo prompts should stay under 75 CLIP content tokens including the modifier. Prepared photos and text are conditioning, not weight training.
3. Site realism is a prototype; use diagnostic=true and say so. On Intel XPU set video_model="ltx" (LTX-Video 2B distilled, 512x320, 24fps): 2s takes about 5 min, 8s about 22 min, 15s about 40 min with continuous=true. For 16:9 first frames set aspect="16:9" (512x288, no squeezing, 10% fewer tokens) and import them with `video.cmd import --aspect 16:9` (`--keep` leaves pictures someone handed over in place). LTX reads 128 prompt tokens (about 90 words) and silently cuts the rest; the digest warns `prompt_truncated`, and text_tokens=256 reads about 180 words. On a fixed tripod/mast shot anchor_end=0.5 (the first frame is also a keyframe near the end) keeps the worker count constant, but over 15s it pulls moving subjects back to their opening places or makes the framing breathe, so the key action is lost; when anything must end somewhere else, use keyframes (step 4). Do not anchor a camera that rides on a moving machine. Prefer in-place actions (digging, lifting); travelling vehicles leave the frame on long clips. decode="lean" halves the repeated VAE decoding (about a third of a 15s job); "safe" stays the default until lean is verified. The digest's `timing` shows text, load, per-step denoise and decode seconds. Neo (384x256) darkens after about 4s. Do not join clips, interpolate or slow playback to imply natural continuity.
4. Moving equipment (approach and stop, pass by): condition one generation on keyframes of the same tripod shot. Make the start frame with GenerateImage, then edit it into a middle and an end frame where only the equipment has moved (same orientation; it gets larger only when it really comes closer). Run `video.cmd compose-end <start> <edited> <out> --keep x0,y0,x1,y1` to copy every static region (worker, background, sky) from the start frame, because image edits redraw them slightly and the video model turns that into camera motion. Request: anchor_end=0.9, anchor_end_image=<end>, keyframes=[{"image_path": <middle>, "at": 0.5}], cond_noise=0. Without the middle keyframe the camera drifts toward approaching equipment mid-clip. Image edits do not move a person to a stated spot reliably (they teleport or reframe); to make a worker walk, edit a clean plate without the worker, then `video.cmd paste-region <frame-with-worker> <plate> <out> --box x0,y0,x1,y1 --at x,y --clean <plate>` places the same worker pixels at each keyframe position (only pixels that differ from the plate are pasted). A generated plate never matches the real background exactly, so for workers in PPE prefer `--ppe --solid 0` (silhouette from orange, yellow or fluorescent lime vests, white, red or yellow helmets and dark clothes, holes filled row by row); a see-through or holed worker in a keyframe becomes a smear in the video. A worker hidden behind an object in the start frame cannot be pasted whole: edit them in full body at the new spot and paste from that edit. Image edits redraw a large vehicle in place instead of moving it and overshoot small moves (a basket asked to rise 30 cm rose into the beam), but they remove a machine well: edit a plate without it, then `video.cmd move-object <frame> <plate> <out> --box x0,y0,x1,y1 --shift dx,dy [--scale s --pivot x,y]` moves the machine's own pixels (boxes tight around it, repeatable; scale above 1 means closer) and fills what it uncovers from the plate. A machine cut off by the frame edge may only move toward that edge, or its cut shows; if the action goes the other way, keep the original frame as the end keyframe and build a new start frame (pass it as image_path). Verified on a 15s tower clip: start + middle (at 0.45, strength 0.9) + end (anchor_end 0.9) gave the key action with a locked camera. For a camera riding on a machine, an end keyframe of the travel is `video.cmd zoom-key <first> <end> --zoom 1.08 --fixed-bottom 0.08` (the opening view magnified about `--centre`, the point travelled toward, which stays put; the machine part at the bottom left as it is); this recipe is not yet verified on a clip.
5. First frame decides the result. Best: Cursor GenerateImage (16:9 static tripod shot with every subject fully visible), then `video.cmd import <image>`, which moves it into `<runtime>\assets\first-frames` cropped to 16:10 and deletes the original; pass that path as image_path. Without image generation use `video.cmd frames <spec>` (SD1.5 seeds on one contact sheet); it struggles to place equipment and a worker in one frame. Reference images must be inside the chosen runtime folder. Keep attribution with a licensed photo. Neo GPU uses original bf16_stream; leave cpu_precision unspecified. CPU preview can use INT8. Wan 1.3B supports text only and rejects image_path. It needs substantially more RAM and is diagnostic, not the Gram default.
6. Do not watch a running job. For one job, check back later with video_digest (a 2 KiB summary with stage times, memory, GPU use and darkening/colour-collapse/static warnings; `little_motion` means no subject visibly moved, `camera_moved` means the view itself zoomed or shifted, which fails a locked tower or tripod shot). For several runs, write a plan and run `video.cmd plan <file>` in the background, then end the turn; read only its summary. Cancel with video_cancel. Show a completed MP4 only after required safety checks and full decoding succeed. Review worker count, bodies, PPE, boom joints, tracks, contact and camera motion. Frame variation and successful GPU kernels do not prove realism. Never bypass a rejected safety output.
7. After recording a round, preview `video.cmd clean`, then run `video.cmd clean --apply`. It deletes failed or cancelled jobs, finished jobs not named in reports/STATE.json after 3 days, old clip caches, leftover scratch and dead request-index hints. It keeps jobs named in STATE.json (write a job id there to keep evidence), queued or running jobs and models. It warns `low_free_space` below 10 GiB free on the runtime drive; stop generating if cleaning does not fix that.

Keep normal results compact; raw result.json contains device, kernel calls, peak explicit GPU buffers and phase RAM/time. These are current-host measurements, not Iris/Gram benchmarks.
